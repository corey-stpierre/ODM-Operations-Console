Start here: connect, inspect, preview

QUEST ODM OPERATIONS CONSOLE
1. Extract the complete package into a new folder; use one of the Start-QuestODMConsole launchers.
2. Open Diagnostics. Check the installed Quest module and run readiness. Read individual warnings; a local test pass does not establish tenant permissions or licensing.
3. Connect using the correct region. For Microsoft 365, select the organization, project, and workload. For Active Directory/devices, select the organization, open the Active Directory tab, and click Open Active Directory workspace; no M365 project is needed. Confirm both source and target tenants in Quest.
4. Refresh the workspace. Use Users, Tasks, Collections, and the workload inventory to inspect discovered objects.
5. Start with a small pilot. Preview its CSV or operation, read defaults and object scope, then enable changes for the exact active context.
6. Execute only after the local execute control and confirmation. In Operations Center, new tasks remain held; start them deliberately from Tasks after inspecting settings and memberships.
7. Read the generated report before retrying. A timeout or rendering error does not undo service changes.

Safe Mode resets on context changes. The Mapping Collision Utility is read-only and runs separately. Keep reports with your migration runbook.

RELEASE STATUS
This is an RC candidate for offline and pilot evaluation. Tenant-connected acceptance and signing must be recorded before production approval. The web console still owns administrative setup, and functions identified in the coverage table. The console does not claim exhaustive native web-console parity.

Which console area to use

Overview: inventory counts, selected context, running/failed task counts and last refresh.
Users: look up discovered accounts, inspect memberships and add/remove individual account memberships.
Tasks: inspect task details and events; load members; start, stop or delete selected tasks; preview/apply account membership CSVs; request error-log exports.
Collections: inspect collections and account members; create/delete collections; preview/apply account membership CSVs.
Task Factory: batch account Mail, OneDrive, Meeting Link and Mailbox Switch tasks by collection. Choose direct settings or verified saved templates. Review the mail cutoff date; it is persisted, not automatically advanced.
Bulk Operations: account discovery/mapping, membership reports and removal plans, collection creation/removal, task lifecycle CSVs, exports, cross-project task deletion and Mapping Collision Utility.
Teams / SharePoint / Power BI: inventory and guarded ObjectId CSV collection/task creation across ten established workload task routes.
Operations Center: 104 enabled task constructors and 65 task-update forms with the installed module's field descriptions and valid choices. Includes the additional workloads and task options. Unavailable commands are shown with a reason.
Diagnostics: environment, module compatibility, readiness, operation history, local logs, retention and support bundle.
Guides: this manual, samples, official documentation, and Quest web-console access.

Account membership screens remain account-oriented. Use typed object fields in Operations Center for Power BI and Power Platform objects. Inventory choice controls member ID interpretation; choose the matching kind before previewing.

Active Directory: separate organization context for directory objects, environments, workflows/runs/logs, device profiles/jobs, file shares and self-service migration. Includes 27 inventory types and 20 guarded action forms with OdmApi 2.1.401. Setup, new profile creation, agent deployment and other web-only settings use the Quest setup button.

Operations Center: complete workflow

1. Select your workload and click Load workload operations.
2. Choose a task type. Fill Name and other required fields. Type names, numbers and file paths as text; do not add PowerShell quotes, switches or expressions.
3. Optional blank fields and Use Quest default are omitted from the command. The preview lists the module's documented default expressions. These are not custom console presets. Read conditional descriptions carefully: some choices require another field or input file.
4. Boolean choices are true/false. Dates other than scheduling require ISO format with a timezone, for example 2026-11-01T00:00:00Z. Enum fields offer only recognized names.
5. Typed fields such as Workspaces, Gateways, Connections, Environments, Profiles or Object take exact Quest IDs separated by commas. They are looked up again within the selected workload. Object takes exactly one ID. These are not Microsoft GUIDs, names or URLs unless Quest's inventory itself uses that identifier.
6. For tasks that accept membership after creation, use the optional Task member IDs box. Use Inventory to copy selected IDs. For typed fields, paste IDs into the matching field instead.
7. Review scope. Leaving selectors blank can mean all objects in the workload when the task runs. The acknowledgement is required even for a small selection.
8. Preview and read the result: parameters, omitted defaults, template values, scope, input hashes and schedule. Password fields are masked and redacted from reports.
9. Enable changes globally, enable the operation locally, then Create held task or Apply task update. A preview expires after 15 minutes, a context/input change, or one execution.
10. Inspect the actual task in Tasks and Quest before starting it. Some vendor commands normalize task names or apply conditional defaults. The console never automatically starts these newly created tasks. An explicitly scheduled update can start an existing task automatically.

PREVIEW means no mutation command was submitted; reads may occur.
CREATED_HELD means Quest returned an identifiable task whose held state was confirmed and any requested post-creation membership passed readback.
REVIEW_REQUIRED means creation, membership or readback was not fully confirmed. The report preserves any known TaskId. Inspect Quest before retrying; earlier steps may have succeeded. No automatic rollback or create retry occurs.

For an update, choose the matching Update operation and supply its exact Task ID. Optional blank fields preserve the current settings. ScheduledStartTime accepts a future ISO timestamp with timezone, or hold to remove the schedule. Scheduling enables automatic execution. Active tasks and wrong task types are blocked. UPDATED_REVIEW_REQUIRED means the setter returned and the task was read back; compare its actual settings in the result and Quest. It is not an automatic guarantee that every requested field took effect. Reload Operations Center when you change modules or workload.

CSV basics and common errors

Use a comma-separated UTF-8 file with exactly one header row. Preserve header spelling. Do not use semicolons or localized Excel separators.
Every row must contain the same number of fields as the header. Duplicate/blank headers, missing/extra fields and malformed quotes are rejected. A header-only file is empty. Blank lines are ignored.
Quote values containing commas, line breaks or quotes. A quote inside a quoted value is doubled:
CollectionName,SourceUPN
"Wave 01, Finance",alex@source.example

Keep IDs as text in Excel; avoid scientific notation and trimming leading zeros. Replace every placeholder in a sample. Use ASCII file names for native Quest uploads; account discovery/mapping files are limited to 15 MB.
Use exact IDs when names are duplicated. Exports may contain private identities: store them in your approved migration location.

There are TWO DIFFERENT kinds of CSV:
A. Console CSVs: batch collections, memberships, task factory and lifecycle. Their columns are listed in the next topics and Samples.
B. Quest native upload CSVs: file-based discovery/mapping and other workload operations. Each task can have a different schema. Use the exact wizard example or the documented sample for that operation. A console CollectionName/ObjectId CSV is not a Teams, SharePoint or Power BI mapping file.

Operations Center validates file existence, hashes and CSV structure. It validates selected known schemas; it does not claim that generic parsing validates every vendor-specific column rule. Where no schema is provided, download the example from the matching Quest wizard and follow its requirements.

CSV: accounts, memberships and Task Factory

Users.csv: SourceUPN. Other supported identity headings include SourceUserPrincipalName, UPN, UserPrincipalName, SourceEmail and Email.
CollectionsAndUsers.csv / TaskFactory.csv: CollectionName,SourceUPN. One row per source account and collection. Task Factory groups by CollectionName, deduplicates account memberships and applies the selected task types/settings to each group.
TaskRemovalPlan.csv: TaskId,TaskName,ObjectId,SourceUPN. Prefer exact TaskId and ObjectId from the generated removal plan. Do not edit IDs independently of their names.
RemoveCollections.csv: CollectionName,CollectionId. Supply exact CollectionId when collection names are not unique.
TaskReferences.csv / DeleteTasks.csv: TaskName,TaskId. Exact IDs take precedence. Duplicate task names are rejected where resolution would be ambiguous.
DeleteTasksAcrossProjects.csv: TaskName,ProjectId,ProjectName,TaskId. ProjectId identifies the target Quest project/workload context. The original context is restored and verified after processing. Preview every cross-project operation.
ObjectLookup.csv: SourceEmail. Generates matched/unresolved reports for review.

ACCOUNT DISCOVERY (native Quest file)
UserPrincipalName,Type OR ObjectId,Type. Do not mix identity formats. Use the matching example in Samples and supported account type values.
ACCOUNT MAPPING (native Quest file)
SourceUPN,TargetUPN OR SourceObjectId,TargetObjectId. Keep both columns from exactly one format. Additional target profile columns are available in AccountMappingByUPNTemplate.csv.

Legacy batch routines may process valid rows/groups while reporting invalid or unresolved rows. Do not assume every batch workflow is transactional or has all-or-nothing validation. Review all result files. Content CSV workflows have whole-file validation before writes.

CSV: Teams, SharePoint and Power BI batches

Use the Teams / SharePoint / Power BI tab to export inventory, then fill the batch columns.
Collections require: CollectionName,ObjectId
Collections and tasks require: CollectionName,ObjectId,TaskName
Recommended guards: WorkloadId,ObjectKind

Keep the exported Quest ObjectId unchanged. A native Microsoft workspace ID, site URL or team name is not interchangeable with the Quest ID. Power BI inventory shows WorkspaceId separately.
ObjectKind is Teams, Groups or Chats; SharePoint; or Workspace, Gateway or Connection. Select the same kind in the UI. All rows must belong to the active workload. One task name must belong to exactly one collection per file.
Example:
CollectionName,ObjectId,TaskName,WorkloadId,ObjectKind
Wave01,replace-with-quest-object-id,Wave01 - Provision,replace-with-workload-id,Teams

Any invalid row blocks the whole content batch before writes. Duplicate membership rows remain in reports but membership is deduplicated. Existing task names are skipped, not repaired or overwritten.
Template-based tasks require an exact template ID owned by the selected project/workload with the matching task type. Preview displays settings. Template schedules are not reused.
Power BI direct tasks require the target admin UPN and use the settings displayed by the console. Collection/task membership is verified. Readback delay or partial failure is reported for review.
All rows use the same task kind and settings; use separate files for different templates/options. Follow Quest limits when sizing waves. See WORKLOAD_GUIDE.txt for the established ten routes. The Operations Center provides the additional task types.

Teams mapping file example: QuestTeamsMapping.csv
SourceMailNickname,TargetMailNickname
source-team,target-team
Use the supported case-sensitive mail-nickname headers. These are team/group mail nicknames, not display names. Multiple source mappings to one target can merge content. Review the target and OneNote implications in Quest documentation.
Source: https://support.quest.com/technical-documents/on-demand-migration/current/user-guide/17

Power BI workspace mapping: QuestPowerBIWorkspaceMapping.csv
Source Workspace Name,Target Workspace Name
Source Finance,Target Finance

Power BI gateway mapping: QuestPowerBIGatewayMapping.csv
Name,Target Gateway
Source Gateway,Target Gateway

Headers are case-sensitive. Target gateways must already be configured before mapping and migration. Use the exact example from the relevant wizard if Quest changes its format.
Source: https://support.quest.com/technical-documents/on-demand-migration/current/user-guide/35

These files belong in the matching Operations Center FilePath field. They do not belong in the console's Content CSV batch workflow. Download the appropriate Quest wizard example for SharePoint site/web/list/term-store mappings, Power Platform property mappings and other native formats.

Workload sequence and prerequisites

Accounts and user data: establish discovery and matching/mapping; inspect identity collisions; review account/group provisioning; then plan mailbox, OneDrive, permissions, meeting links and cutover tasks. Coexistence, address rewriting and Desktop Update Agent have their own prerequisites.
Teams/groups/chats: discover objects and map identities, plan mappings/renaming, provision targets as needed, collect statistics, migrate and validate. Deletion and reset operations require separate review of scope.
SharePoint: discover sites and contents, match/map sites, webs and lists, review term stores and permissions, run a pilot, compare content and validate before cleanup. File-based list-item migrations need the vendor's exact file format.
Power BI: test connection, discover workspaces/gateways/connections, configure target gateways and identity mappings, review connection profiles and admin ownership, validate migration access, provision, migrate connections/workspaces, and refresh permissions/statistics as appropriate.
Power Platform: test connection, discover environments and content; inspect apps, solutions, flows, connections and dataflows; map target dependencies, billing/group/name settings and solution package locations; validate, provision, migrate and remediate in the order required by Quest.
Public folders: discover, map, collect statistics, provision as appropriate, migrate content and validate access. Hybrid Exchange tasks remain restricted to the Hybrid Exchange workload.
Desktop Update Agent: confirm deployment, supported clients, permissions and notifications before generating/revoking tokens or switching applications. Custom scripts and cutover tasks need pilot testing.

These are navigation aids, not a replacement for the current Quest workload prerequisites, permissions reference and service limits. The console preserves the vendor's conditional options; readiness cannot prove every migration prerequisite.

Templates, defaults, dates and notifications

Saved Quest templates are task configurations, not arbitrary JSON files. Use the exact template ID and confirm ownership/type. Review the preview's template content before creation.
The existing Task Factory exposes its four account task templates. The content CSV tab validates its workload task templates. Operations Center offers TemplateId only where the installed command exposes it; unsupported type contracts are blocked.
A blank optional field uses the installed Quest command default. Default displays such as $false, $null or [Enum]::Value describe vendor defaults; do not type those PowerShell expressions into the field.
Use explicit true/false values in choices. Dates use ISO timestamps with Z or an offset. Review whether a date filters source content; a date filter is different from a task schedule.
Operations Center always creates held tasks. Existing-task changes use the matching Update form. Blank means unchanged; hold removes the schedule; a future ISO timestamp schedules automatic execution. Available settings depend on the loaded module. Task start/stop/delete remain in this console.
Notification options depend on the task. Enabling notification may expose recipient and failure-only options. Check recipient details before submitting; task notification behavior is handled by Quest.
Password fields are masked and excluded from preview/report values. Exported Quest template files retain their actual configuration for re-import; inspect and protect these files because vendor template values can include credentials. Do not put credentials into ordinary name, path or description fields. Clear or close the form after sensitive operations.

Management: templates, collections, events and reports

Open Operations Center > Templates, reports and management. Choose an inventory kind, load it, then select a row to fill its exact ID. Choose the intended action; fields not relevant to it can stay blank.

RENAME COLLECTION: use the current workload collection ID and a unique new name. The name is read back after submission; VERIFIED confirms the match.
SAVE TASK AS TEMPLATE: use the exact task ID and a unique template name. Quest strips its standard runtime fields and saves settings in the current project. Inspect the resulting template before reuse. Saving is not migration execution.
IMPORT TEMPLATES: browse to a Quest-exported JSON file. Every entry must have Name, TemplateType and JSON-string Values. Types must match the current workload and Values.type; duplicate names and unsupported export versions are blocked before writes. The service import itself is not transactional: after a timeout, inspect existing templates before retrying the file.
EXPORT TEMPLATE: select the exact template ID. Export writes a new portable Quest JSON file under Reports and is allowed in Safe Mode. Export is deliberately faithful to Quest configuration and is not a sanitized support bundle. Protect credentials or sensitive tenant settings inside it.
ACKNOWLEDGE EVENT: load current events and select the exact ID. Acknowledgement marks the event obsolete in Quest; it does not repair the underlying migration failure.
REPORTS: view report metadata for the parent project. The inspected Quest API limits this listing to 1,000 records. Use the web console for report-file downloads, larger histories and vendor dashboards.

Preview before applying. Service writes require global changes enabled and the local execute checkbox. A preview lasts at most 15 minutes and is tied to context and source/input state. SUBMITTED_REVIEW_REQUIRED means the command returned but the full resulting service state was not verified. REVIEW_REQUIRED preserves any response/error after an uncertain write. Refresh the matching inventory and inspect Quest; do not automatically replay.

Use Guides > Quest web console for administrative setup, consent, licenses/roles, address rewriting and unsupported wizard options.

Reports, recovery and troubleshooting

Inspect the result status, TaskId/CollectionId and generated report together. A green dispatcher completion does not by itself mean every row succeeded; read statuses such as INVALID, SKIPPED_EXISTING, NOT_VERIFIED and REVIEW_REQUIRED.
A service call can succeed before a network timeout or UI error. Refresh Quest and identify the created object before retrying. Console workflows do not roll back prior successful changes.
Operations Center writes a report before creation and updates it with any returned TaskId before membership work. Never automatically replay a SUBMITTING or REVIEW_REQUIRED report.
For stale context, reconnect and reselect organization/project/workload. Rerun readiness after fixing a failure; feature blocks remain until reassessment.
For missing inventory, verify workload kind, discovery completion, account role, consent and permissions. Empty results are not evidence of successful discovery.
For unsupported commands or parameter changes, check the loaded OdmApi version in Diagnostics; do not assume an unvalidated newer module is compatible.
For task failures, inspect Tasks > Details/events, export details, and request the Quest error-log export. The support bundle sanitizes common credential patterns but operational reports still contain identities and context identifiers.
Log retention protects the current session log. Historical pruning is separate from operational CSV/report retention. Back up required audit evidence before clearing history.

Run offline acceptance on both supported hosts, then use a designated nonproduction Quest project for connected acceptance.
For every workload used in production:
1. Authenticate, select context, refresh, and run readiness.
2. Compare inventory counts and sample IDs against the web console.
3. Preview representative valid and invalid files. Confirm zero service changes for preview or blocked requests.
4. Create one small held task, verify all effective settings, scope, type, membership, notifications, schedule and ownership in Quest.
5. Exercise start/stop on an approved pilot task; confirm event/report accuracy and observed service behavior.
6. Test duplicate names, changed files/context, expired previews, permission denial, throttling, network interruption and uncertain readback.
7. Validate workload-specific results with source/target owners before cutover.
8. Review account collection batches, cross-project restore, task factory templates and the read-only collision utility.
9. Record operator, date, module version, workload, task IDs, expected/actual results, report paths and disposition in the supplied PilotAcceptance.csv.
10. Resolve blockers, decide the outstanding web-console handoffs, sign the release and re-create manifests/package after signing.

Do not label offline mocked tests as live Quest validation. Code signing is a release-owner action with an approved certificate.

Active Directory: start and prerequisites

AD AND DEVICE WORKSPACE
1. Configure your AD migration project, environments, directory synchronization workflows and required profiles in the Quest web console. Confirm licensing, role permissions, connectivity, service accounts and current vendor prerequisites. Deploy/register the required Quest agents using Quest's deployment instructions.
2. Connect in this console to the right region and select the Quest organization. An AD-only organization can be selected without a Microsoft 365 project. Open Active Directory workspace. The console clears its M365 selection and returns to Safe Mode.
3. Load Environments, Workflows, Devices and the relevant profiles. Check exact IDs, source environment, target environment and existing assignments. AD IDs are usually positive integers. They are different from M365 object/workload GUIDs. Self-service IDs are opaque strings: copy them exactly.
4. Start with a designated nonproduction pilot. The console does not infer migration readiness from the existence of an object. Review Quest discovery, mappings, permissions, ReACL results and vendor prerequisites before credential caching or cutover.
5. Choose an action, provide exact targets and any required reference IDs, then Preview. No mutation is submitted during preview. All targets and references are read again before execution.
6. Read the preview, enable changes for the AD organization, acknowledge the local impact control, and enter APPLY AD ACTION. Most AD actions can begin immediately. They are not the held tasks created by the M365 Operations Center.
7. Inspect jobs, workflow runs/logs and the Quest web console. SUBMITTED_REVIEW_REQUIRED means the command returned, not that migration completed. For uncertain or partial failure, do not resubmit the original batch: reconcile every target first.

Return to Microsoft 365 by selecting a project and workload in the header. Changing organization/project/workload or reopening AD invalidates its preview and resets Safe Mode. AD inventory is scoped to the selected organization, which may include several environments; use environment IDs and exact selections to constrain the pilot.

The M365 Accounts workload's internal API name can include activedirectory. That legacy workload is not this separate ODM AD/device workspace.

READINESS
Diagnostics readiness recognizes the AD workspace. It checks host/storage and installed AD command availability, skips M365 project/subscription checks, and explicitly warns that AD licensing, roles, agent health, connectivity and migration prerequisites still need your verification. A catalog or host pass is not tenant migration approval.

Active Directory: actions and settings

DIRECTORY WORKFLOWS
Start Workflow launches an existing configured directory-sync workflow. Review mappings, scope, test mode, scripts and schedules in Quest first. This console does not design or schedule directory-sync workflows. Monitor WorkflowRuns, then WorkflowLogs using the run ID in Parent ID.

DEVICE ACTIONS
Discovery refreshes device discovery through Quest. ReACL submits Quest permission processing. Cache Credentials requires a credential-cache profile. Custom Action runs the preconfigured Quest action: review its script and scope in the web console before selecting its ID.
Cutover requires exact cutover credential, migration profile and network profile IDs. Entra ID Cutover requires an Entra ID join profile. Offline Domain Join requires a cutover credential. IgnoreReACLStatus=true explicitly bypasses Quest's ReACL-status prerequisite; false keeps it. These operations may affect sign-in, domain membership and connectivity. They require your reviewed migration runbook and pilot.
Cleanup is a vendor cleanup operation; review its consequences before submission. It is not a general undo button.

DEVICE AND PROFILE SETTINGS
Set Device assigns existing target environment, migration wave and supported profiles/credentials. Reference fields take IDs, never passwords. SelfServiceProfile assignment is a web handoff because the inspected API has no getter to resolve it safely.
Set Interactive Profile changes an existing shared profile (name, cancellation, postponement, unattended behavior and timeout limits). Set ReACL Profile changes an existing shared permission-processing profile. Update flags control which object/resource categories Quest processes. Only supplied fields are changed. A shared-profile update can affect devices outside the target list. Edit one profile per action and inspect it in Quest afterward.
The ReACL WhatIf field is a stored Quest profile setting. It is NOT this console's preview switch. Review its vendor semantics before use; an action that changes it is still a write.
ReACL LocalFolders/ExcludePaths/ExcludeRegistryKeys/ExcludeFiles/ExcludeSecurityIdentifiers/ReparsePointRules take one item per line, preserving commas in each item. Apply Quest's exact path, identifier and rule syntax. For clearing lists or other null/reset semantics, use the web console; blank console fields are omitted. The enum dropdowns show only values exported by the installed module.

FILE SHARES
Start file-share ReACL, ReACL Rollback or Cleanup against exact FileShares IDs. File-share ReACL Rollback applies to that vendor permission-processing operation; it does not roll back a device cutover, workflow run or entire migration. New shares and their profile design remain in the web console.

SCHEDULING
When offered, DoNotStartBefore is an earliest permitted start, not a held task or a promise to execute at that exact time. Use future ISO 8601 with a timezone, such as 2026-11-15T22:00:00-06:00; keep it at least a minute ahead when applying. Blank allows immediate processing. Workflow Start and self-service Migrate Now are immediate submissions. Service/agent availability and vendor rules determine actual execution.

SELF-SERVICE
Use SelfServiceDevices or SelfServiceUsers inventories, retaining their opaque IDs exactly. Enable/disable self-migration and remove scheduled migrations using the matching action. NotificationTemplateId is the exact GUID from Quest; the API does not expose a template inventory. Review SendNotificationTo choices: these actions can send notifications. Optional ScheduledMigrationTime must be a future ISO timestamp with timezone. Device Migrate Now may start immediately. Self-service service errors or an unexpected updated count produce REVIEW_REQUIRED.

WEB CONSOLE HANDOFFS
Project/environment creation and design; directory mappings, synchronization rules, workflow design/schedules and scripts; agent download/deployment/registration; new profiles, credentials, network configuration, waves and shares; self-service templates/setup; role/license administration; job controls not exported by this API; full vendor dashboards and any unsupported setting. The portal button opens Quest without transferring authentication or performing changes.

Active Directory: inventory, CSV and recovery

INVENTORY AND MONITORING
Choose an inventory and Load inventory. A query returns up to the selected limit (default 1000, maximum 100000); this is not a guarantee of complete pagination. Narrow filters or use exact IDs. Native Filter uses Quest's syntax; self-service uses SearchQuery. The console does not evaluate these fields as PowerShell.
Exact ID cannot be combined with Parent ID or Filter. DeviceJobs needs a device ID in Parent ID, or an exact job ID. WorkflowLogs needs a workflow-run ID in Parent ID. WorkflowRuns can be listed or looked up by exact run ID. Logs and agent configuration do not have action target IDs. Nested SDK objects are omitted from details to avoid cycles; use the corresponding inventory or Quest for full navigation.
Select rows to read safe details. Copy IDs / use for matching action fills the target box only when the inventory kind matches the selected action. Export CSV writes the currently loaded rows, not every tenant object. Agent/service/authentication keys, password fields and global-variable values are hidden. Store exports/reports as migration data: names, paths, UPNs and environment IDs can still be sensitive.

TARGET CSV
Required: OrganizationId,TargetId
Optional guards: EnvironmentId,Kind
An exported AD inventory already contains these columns. Reduce it to the approved pilot rows before using it as an action file. The exported Name, Status and Details columns are ignored on import. Other unknown columns are rejected so misspelled guard columns cannot silently lose their protection. No per-row action settings are supported: every row uses the selected form's settings. Use separate files for different profiles/options.
Example (replace placeholders with exported values):
OrganizationId,TargetId,EnvironmentId,Kind
replace-with-quest-organization-guid,123,7,Devices
replace-with-quest-organization-guid,124,7,Devices

Use UTF-8, comma delimiters and a header row. Quote a value that contains a comma. Do not alter ID formatting in a spreadsheet. Self-service IDs must be copied exactly; do not convert them to integers or substitute Microsoft object IDs. Provide typed IDs OR a CSV, not both. Duplicate, missing, wrong-organization, wrong-kind or mismatched-environment rows block the batch before mutation. Target lists are limited to 1000; shared-profile edits allow one target.
EnvironmentId is an optional source-environment guard for models exposing that field. Use it for Devices. It is not a universal field for every inventory. For other kinds, omit it if it is not present in the exported inventory; inspect their details instead.

REPORTS AND RETRIES
Preview records the organization, region, exact target snapshots, settings, reference configurations, CSV hash and immediate/scheduled behavior. Its token lasts 15 minutes and can be used once. Changed targets/settings/context or a modified CSV require a new preview. The console rechecks configuration but cannot lock Quest objects against simultaneous external edits; keep a single operator for a pilot.
Each application writes a local journal before each submission. SUBMITTING with no final result means the outcome is uncertain. SUBMITTED_REVIEW_REQUIRED means the submission returned, not that all settings or migration outcomes were verified. REVIEW_REQUIRED stops the remaining batch; targets marked NOT_SUBMITTED were not dispatched by this run. Inspect jobs/workflow logs and the web console before deciding whether a target needs another action. There is no automatic retry or rollback.
Reports retain known returned job IDs and before/response snapshots but do not serialize nested service objects or secrets. For shared-profile changes, compare actual values in Quest after the setter returns. For self-service, reconcile notifications and final device status as well as updated counts.

PILOT ACCEPTANCE

Use Samples/ActiveDirectoryPilotAcceptance.csv to record organization-only selection, inventory/filters, a reviewed workflow, a discovery job, profile readback, ReACL and file-share actions, each approved cutover variant and self-service notifications/scheduling. Do not run destructive/cutover actions merely to fill out a checklist. Perform only approved pilot scenarios with a recovery runbook.
